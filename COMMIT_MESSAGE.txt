# Fix: Exception Handler Parsing in CALL Statements

## Summary
Fixed critical bug where NOT ON EXCEPTION clauses were incorrectly merged with ON EXCEPTION clauses in COBOL CALL statements. Enhanced the CallStatement model to properly distinguish between exception and success paths.

## Changes

### cobolparser/models/statements.py
- Added `not_on_exception` field to CallStatement class
- Allows proper separation of ON EXCEPTION and NOT ON EXCEPTION handlers

### cobolparser/parser.py  
- Fixed exception handler parsing logic in _parse_call_exception_handlers()
- Changed from continuing in ON EXCEPTION loop to dedicated NOT ON EXCEPTION parsing block
- Both handler types now properly captured in separate lists
- Integrated NOT ON EXCEPTION parsing directly after ON EXCEPTION detection

### cobolparser/models/program.py
- Updated get_all_statements() to traverse not_on_exception field
- Ensures complete AST traversal includes statements from success path

## Semantic Impact

**Before**:
```cobol
CALL WS-PROG USING WS-VAR
    ON EXCEPTION
        DISPLAY 'Error'
    NOT ON EXCEPTION
        DISPLAY 'Success'
END-CALL.
```
Both statements were in on_exception list (incorrect).

**After**:
```
on_exception: [DISPLAY 'Error']
not_on_exception: [DISPLAY 'Success']
```
Properly separated execution paths (correct).
