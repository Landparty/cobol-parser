# cobolparser Silent-Drops-and-Gaps Audit (2026-07-09)

Scope: full pipeline (preprocess → lex → parse → AST → serialization) plus the
static-analysis layer, following up on the 2026-07-06/07/08 audits (C1–C8,
H1–H7, M5/M8/M10, tier5) whose findings are already fixed on `main`. Method:
four parallel, independently-scoped code reviews — DATA DIVISION parsing, the
15 analysis modules, the statement parsers not deeply re-audited since
2026-07-06, and AST serialization completeness — each briefed on the prior
audits' fix lists so it would not re-report closed issues. Every finding below
was reproduced at runtime before being fixed.

## Verdict

The AST-serialization layer is now clean: the review confirmed that every
parser-populated, source-derived attribute in `models/` reaches `to_dict()`
(the only unconditional omission, `IOWriteStatement.advancing_mode`, is
genuinely redundant with `advancing_clause`). The other three reviews each
found real, runtime-reproduced silent drops:

- The **highest-impact** finding is in the analysis layer, not the parser:
  `ProgramFlowAnalyzer` silently dropped every control-flow edge nested inside
  an IO / arithmetic / STRING conditional clause body, which cascades into
  **false "unreachable paragraph" reports** and missing flowchart arrows on
  ordinary, well-formed programs (a `READ ... AT END PERFORM x` is completely
  routine COBOL).
- A **new DATA-division drop** (OCCURS `ASCENDING/DESCENDING KEY`) that also
  cascaded into losing a following `INDEXED BY` — and the observation that the
  DATA division, alone among the division parsers, had **no** warning channel
  for clause tokens it drops.
- Four **statement-parser operand drops** (REWRITE FROM, START KEY data-name,
  ACCEPT format phrase, STOP RETURNING), two of them for common, standard
  constructs, one of which additionally corrupts program structure by
  injecting a **phantom paragraph**.

All fixes are verified by the existing suite (6,720 passed after adding 13 new
regression tests, up from 6,707), with zero regressions, and by rebuilding the
Cython extensions (Cython 3.2.4) to confirm compiled/pure-Python parity.

## Findings and fixes

### 1 — ProgramFlowAnalyzer drops edges nested in IO/arithmetic/STRING clause bodies **[verified, fixed]**
`cobolparser/analysis/program_flow.py`, `_scan_paragraph_statements` → inner
`scan()`. The flow graph is built by a hand-rolled recursive walk that
special-cased only PERFORM inline blocks, CALL exception handlers, and
IF/EVALUATE/SEARCH/RETURN. It never descended into IO clause bodies
(`AT END` / `NOT AT END` / `INVALID KEY` / `NOT INVALID KEY` / `AT EOP`),
arithmetic `ON SIZE ERROR`, or STRING/UNSTRING `ON OVERFLOW`. A PERFORM/GO
TO/CALL living in one of those produced no edge. Repro:
`READ f AT END PERFORM EOF NOT AT END PERFORM PROC END-READ` yielded **zero**
PERFORM edges and reported `unreachable_nodes = ['PROC', 'EOF']` — both
paragraphs are reached. `DeadCodeAnalyzer` (which uses `get_all_statements()`)
correctly did *not* flag them, confirming the inconsistency. Downstream, the
Mermaid/DOT flowchart generators render only `report.edges`, so those arrows
were silently missing from diagrams. Fixed with a final `else` branch in
`scan()` that recurses into `_CLAUSE_BODY_ATTRS` (the same clause-attribute
set `coverage_analyzer._nested_statements` already uses); the `id`-based
`visited` set prevents double-counting.

### 2 — OCCURS ASCENDING/DESCENDING KEY dropped, cascading into INDEXED BY loss **[verified, fixed]**
`cobolparser/parsers/divisions/data.py` (OCCURS branch) + `_data_fast.pyx`
mirror + `cobolparser/models/data_items.py` (`OccursClause`). The OCCURS parser
went straight from the DEPENDING check to `INDEXED`, so a
`{ASCENDING|DESCENDING} KEY IS ...` clause in its standard position (between
DEPENDING and INDEXED BY) was never recognized — its tokens fell to the clause
loop's `else: consume()` — and because that consumed the `INDEXED BY` tokens
too, the index name was lost as well. `INDEXED BY a b` also kept only the last
index. Repro: `OCCURS 5 ASCENDING KEY IS K INDEXED BY IDX` → `indexed_by:
null`, no key recorded. Fixed by parsing one-or-more repeatable KEY clauses
(multiple key data-names each) before `INDEXED BY`, and collecting all index
names. `OccursClause` gained `key_clauses` (list of `{direction, keys}`) and
`index_names` (all indexes; `indexed_by` still holds the first for backward
compatibility), both serialized when non-empty. Mirrored in `_data_fast.pyx`;
`.c` regenerated with Cython 3.2.4 (only `_data_fast.c` changed — the other two
`.c` files are byte-identical, confirming no version churn). `ASCENDING KEY` is
what makes a table valid for `SEARCH ALL`, so this was semantic loss, not
cosmetic.

### 3 — REWRITE ... FROM source silently discarded **[verified, fixed]**
`cobolparser/parsers/statements/rewrite_parser.py` + `IORewriteStatement`
(`models/statements/io.py`). `REWRITE rec FROM data` consumed the FROM operand
with an explicit "no setter on this node" comment and dropped it; the FROM
source is exactly what gets written. Added `from_clause` (+ setter + `to_dict`
key), accepting an identifier or a literal, mirroring `IOWriteStatement`.

### 4 — START ... KEY IS data-name silently discarded **[verified, fixed]**
`cobolparser/parsers/statements/start_parser.py` + `IOStartStatement`. The KEY
data-name (the key the browse is positioned on) was consumed to reach the
INVALID KEY clause but never stored — `key_condition` kept only the operator
(`EQUAL TO`). Added `IOStartStatement.key_name` (+ setter + `to_dict` key).

### 5 — ACCEPT FROM DATE/TIME format phrase dropped + phantom paragraph; ACCEPT/UNLOCK swallow next verb **[verified, fixed]**
`cobolparser/parsers/statements/accept_parser.py`,
`cobolparser/parsers/statements/unlock_parser.py`. `ACCEPT x FROM DATE
YYYYMMDD` captured only `DATE`; the trailing format word was left in the stream
and re-parsed by the procedure parser as a **phantom paragraph** named
`YYYYMMDD`. Now the FROM clause folds a trailing format phrase into
`from_source`. Separately, both parsers accepted *any* non-period token as
their operand, so a missing operand (`ACCEPT` / `UNLOCK` immediately followed
by another statement) consumed the following statement's verb; both now guard
the operand with `is_statement_boundary()`.

### 6 — STOP RUN RETURNING value / STOP numeric dropped **[verified, fixed]**
`cobolparser/parsers/statements/stop_parser.py` + `StopStatement`
(`models/statements/control.py`). Only `RUN` and a string literal were handled;
`RETURNING`/`GIVING <x>` and a bare numeric `STOP n` operand were dropped.
Added `StopStatement.returning` (+ `to_dict` key) and numeric-literal capture.

### 7 — DATA division dropped unrecognized clause tokens with no warning **[verified, fixed]**
`cobolparser/parsers/divisions/data.py`. The data-item clause loop's
`else: consume()` fallback silently discarded any clause it did not recognize
(GROUP-USAGE, VOLATILE, DYNAMIC LENGTH, DESCENDING KEY, ...) — the DATA
division was the only division parser with **no** warning channel, in contrast
to `environment.py`'s `_warn_dropped_select_token`. Added
`_warn_dropped_data_token`, which warns for meaningful tokens (skipping
NEWLINE/WHITESPACE/COMMENT/CONTINUATION), so an unsupported data-item clause is
no longer fully silent. No corpus program regressed (the change is warning-only
and the supported-clause paths never reach the fallback).

## Not fixed (lower confidence / out of scope)

- **`SET ADDRESS OF x TO y` produces an empty SET node.** Root cause is a lexer
  defect: `CobolLexer` greedily matches the `ADD` verb inside `ADDRESS`,
  yielding `IDENTIFIER 'RESS'`. Fixing it touches the hot-path lexer keyword
  matcher and its `_lexer_fast.pyx` mirror; a warning *is* emitted today, so it
  is not strictly silent. Deferred to a focused lexer change. (Confirmed at
  runtime.)
- **CLOSE with multiple per-file options keeps only the first**
  (`close_parser.py` uses an if/elif chain, not a loop) — rare combination
  (`CLOSE f REEL WITH NO REWIND`), partially masked by a warning.
- **PERFORM para-name `<trailing identifier>`** consumed as a candidate TIMES
  count and dropped when `TIMES` does not follow — malformed-input territory.
- **coverage_analyzer `_analyze_paragraph`** detects `has_stop_run`/
  `has_goback`/`calls_paragraphs` only at a paragraph's top level, not inside
  nested clause bodies — no reproducible test-output drop today (those fields
  gate a single optimization; `TestPlanGenerator` does not consume
  `calls_paragraphs`).
