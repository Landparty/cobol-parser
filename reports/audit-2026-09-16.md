## 1 (High) — `ConstantFolder` could record a value that is wrong

`analysis/const_fold.py`'s entire contract is stated in its own module
docstring: **"No generated value may be wrong: exact by construction, or
absent."** Every folded value becomes an
`Expectation(kind="field_equals")` in a `gen-fixtures` bundle — an assertion
a downstream test will be written against. A wrong one is worse than a
missing one.

Two separate defects, both the same mistake: *the check was written in the
same arithmetic as the thing it was checking, so it had no independent
standing.*

**(a) `_exact_divide`'s proof of exactness could not fail.** It divided at
`prec=80` and then multiplied the quotient back — inside the same 80-digit
context:

```python
with localcontext() as ctx:
    ctx.prec = 80
    quotient = dividend / divisor
    if quotient * divisor != dividend:   # never true for the cases it targets
        return None
```

The rounding error in `quotient` is by construction smaller than 80 digits
can represent, so `quotient * divisor` rounds straight back to `dividend`.
Demonstrated:

```
dividend      = 3
divisor       = 0.3333333333333333333333333333334
quotient      = 8.999999999999999999999999999998200...
quotient*div  = 3.000000000000000000000000000000000...   ->  check PASSES
Fraction check: Fraction(quotient) * Fraction(divisor) != Fraction(dividend)
```

**(b) `_fits_exactly` — the last gate before a value is stored — rounded its
own input.** It scaled with `Decimal` operators, which run in the *ambient*
28-digit context, not the 80-digit one the quotient was produced in. So
`abs(value)` alone silently rounded `8.999…9982` to exactly `9` before the
integrality test ever ran, and the value sailed through as an exact fit.

**Together**, with `WS-T PIC S9(9)V9(9)`:

```cobol
COMPUTE WS-T = 3 / 0.3333333333333333333333333333334.
```

| | value |
|---|---|
| exact quotient | `8.99999999999999999999999999999820…` |
| what COBOL stores (truncates toward zero) | `8.999999999` |
| what `ConstantFolder` recorded | `9.000000000` |

A wrong integer digit. Four more reproductions in the regression test.

**Reachability.** A search over 6,174 short-literal expression/scale pairs
found **zero** wrong values — the defect needs an operand carrying more than
~28 significant digits. That is a 29–31 digit numeric literal, which IBM
Enterprise COBOL (this parser's stated target) permits under
`ARITH(EXTEND)`. Narrow, but real, and the failure mode is silent.

**Fix.** Both checks now decide over `fractions.Fraction`, which has no
precision to round to. Separately, a `/` inside a COMPUTE expression tree
divided with a bare `Decimal` `/` and never reached `_exact_divide` at all;
it now does, so `DIVIDE ... GIVING` and `COMPUTE ... /` hold the same
contract. Genuinely exact quotients (`10 / 4` → `2.5`) still fold.

**Why the suite did not catch it.** Every existing test uses short literals,
where the defect is unreachable. It was found by a differential test against
exact rational arithmetic — ground truth computed a different way. That is
the transferable lesson here: a self-consistent round trip proves
consistency, not correctness.

## 2 (Low) — a legal `cobol.yml` value rejected

`config/_yaml.py`'s `_strip_comment` runs before the parser and has to know
which `#` is inside a string. Its backslash-escape branch was a `continue`
in a `for` loop, which advances **one** character — but an escape consumes
**two**. The escaped quote was then read on its own and closed the string it
was meant to sit inside.

An *even* number of escaped quotes re-opened the string and hid the damage,
which is why the common cases all looked fine. An *odd* number left a
following `#` looking unquoted:

```yaml
msg: "a \" # b"     # -> value truncated, then: YamlError: unterminated quoted string
```

Fixed with an index-driven loop. Real trailing comments are still stripped,
and a genuinely unterminated string still errors with its line number.

## 3 (Info) — a `# pragma: no cover` asserting a guard that isn't there

`encoding.py`'s `_encode_binary` marked its `OverflowError` handler
`# pragma: no cover - guarded by _digits_string`. `_digits_string` is never
called in that function. The branch is reachable — a caller handing
`encode_record()` its own row can hit it.

The *asymmetry* the comment was gesturing at is real and correct: the zoned
and packed encoders truncate high-order digits the way a COBOL numeric MOVE
does, while binary refuses a value that has no representation in its byte
width. Verified:

```
COMP     S9(4)  value=99999 -> RecordEncodingError
COMP-3   S9(4)  value=99999 -> 09999c   (truncated)
DISPLAY  S9(4)  value=99999 -> 39393939 (truncated)
```

Nothing the package generates reaches it (`ValueFactory` respects the
PICTURE; a `VALUE` clause is clamped to it), so behavior is left as is —
refusing loudly matches the module's stated posture. Only the false claim in
the comment was corrected, and `.okf/generators.md` now records the
asymmetry.

## Checked and clean

Recorded so the next pass knows where the looking already happened.

* **Static checks** — `ruff`, `black --check`, `mypy cobolparser/`: all
  clean. Full suite: 11,088 passed, 13 skipped, 1 xfailed.
* **Parser robustness** — handcrafted hostile inputs (empty, null bytes,
  400-deep parens, 300-deep IF, `OCCURS 999999999`, `PIC 9(999999999)`,
  unterminated literals) plus ~240 mutations of 40 sample programs
  (truncation, line deletion/duplication, mid-token chops, junk injection),
  under both `COLLECT_ALL` and `FAIL_FAST`: **zero** unexpected exceptions.
  Errors are collected, never propagated.
* **Analyzers** — all 23 analyzer/generator entry points over 95 programs
  (`tests/samples/` + `examples/cobol/shamrice/`) x 5 variants each:
  **zero** crashes.
* **JCL front end** — 20 handcrafted malformed inputs (unbalanced parens,
  dangling continuations, unclosed in-stream data, CRLF, null bytes,
  200-line continuations) plus mutations of both samples: **zero** crashes.
* **Copybook path security** — `../` traversal, encoded traversal, and a
  **symlink inside the search directory pointing outside it** are all
  refused with `PathTraversalError`, through both the Tier-2 directory-index
  path and the Tier-3 filesystem search. `..` as a substring of a filename
  is correctly *not* treated as traversal.
* **Record encode/decode** — `decode(encode(row)) == row` held cell-for-cell
  across an 83-shape PICTURE/USAGE cross product x 2 charsets, and across
  P-scaling (leading and trailing), edited pictures, `OCCURS`, `REDEFINES`,
  all four `SIGN IS` forms, `COMP-1/2`, `INDEX`/`POINTER`, and both byte
  orders. The only two deltas are the documented exemptions (FILLER reads
  back empty; `COMP-1` is float32). Real-world `TRUNC(BIN)` values
  (a halfword holding 30000 under `PIC S9(4) COMP`) decode and re-encode
  byte-identically.
* **Batch / scan fault isolation** — a missing file, a binary file, an empty
  file and a garbage file alongside a good one: all six results returned,
  per-file errors reported on `BatchResult.read_error` / the scan report,
  no run-level failure.
* **Documented surface** — all 45 documented public names in `CLAUDE.md`'s
  Public API section import successfully; all 27 documented CLI subcommands
  respond to `--help`. No drift.
* **`reports/open-findings.md`** — spot-checked 8 of the tracked-open items
  (numeric-edited record images, dead `TokenType.ALL`, dead
  `_compress_doubled_quotes`, unknown column-7 indicators, the dead
  `[[tool.mypy.overrides]]` for `tests.*`, missing `tracemalloc.reset_peak()`,
  Cython `wraparound=False` vs negative slices, dead
  `parse_picture_clause_fast`). **All 8 still reproduce** — that file is
  accurate, not stale. None were re-fixed here; they remain the
  maintainer's tracked calls.

## Not covered by this pass

* The Cython extensions were not built; everything above ran against the
  pure-Python path. The `.pyx`/`.c` items in `open-findings.md` (P-D2, P-D3,
  P-C1) are unexamined beyond confirming they still describe the tree.
* No differential testing against a real COBOL compiler. The encode/decode
  claims rest on the GnuCOBOL probe already recorded in
  `tests/unit/generators/data/test_encoding.py`.
* `analysis/ast_diff.py` (1,717 lines), `xref.py`, `codebase.py` and
  `sql_cics_lint.py` were exercised for crashes but not reviewed for
  semantic correctness.
