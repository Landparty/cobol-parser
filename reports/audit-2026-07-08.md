# cobolparser Silent-Drops-and-Gaps Audit (2026-07-08)

Scope: full pipeline (preprocess → lex → parse → AST → serialization) plus batch and CLI,
following up on `reports/audit-2026-07-06.md` and `reports/audit-2026-07-07.md`, whose
findings (C1-C8, H1-H7, M5/M8/M10) are already fixed on `main`. Method: four parallel,
independently-scoped code reviews — statement parsers, AST serialization completeness,
preprocessing/lexer (including pure-Python vs. Cython parity), and analysis/CLI/batch —
each explicitly briefed on the prior audits' fix list so it would not re-report already-closed
issues. Every finding below was reproduced at runtime before being fixed.

## Verdict

The prior audits' structural fixes (multi-program units, unknown-verb warnings, clause-body
statement parsing) hold up well — the AST-serialization review found essentially nothing left
in that class. This pass instead found a **new instance of the same silent-drop family in
statement parsers that hadn't been re-audited since 2026-07-06** (SORT/MERGE/ENTRY), an
**inconsistency in how deeply the 2026-07-07 unknown-verb warning was applied** (top-level
PROCEDURE DIVISION dispatch vs. a CALL statement's own exception-handler dispatch), a
**previously-unexamined line-number-integrity bug** in both preprocessing functions (blank/
comment/directive lines were dropped outright rather than blanked, silently shifting every
downstream error/warning location — arguably the highest-value finding, since it corrupts
diagnostics for *every* real COBOL file, not just ones that hit a specific construct), and
two **batch/CLI fault-isolation gaps** that were fixed for sibling code paths in 2026-07-07
but missed for `parse_files_with_copybooks` and `coverage generate`.

All fixes are verified by the existing 6,725-test suite (up from 6,709) plus 21 new
regression tests, with zero regressions, and by rebuilding the Cython extensions to confirm
compiled/pure-Python parity.

## Findings and fixes

### 1 — SORT/MERGE clause loop swallows a following un-punctuated statement **[verified, fixed]**
`cobolparser/parsers/statements/sort_merge_parsers.py`: the "remaining clauses" loop in both
`SortStatementParser` and `MergeStatementParser` recognized only a fixed keyword list
(`WITH`/`COLLATING`/`USING`/`GIVING`/`INPUT`/`OUTPUT`); any other token fell to an
`else: token_stream.consume()` fallback with no boundary check — the same bug class the
2026-07-06 audit fixed for INSPECT/STRING/UNSTRING, but SORT/MERGE were missed. Repro:
`SORT f ... GIVING g` (no period) immediately followed by `DISPLAY 'DONE'.` silently dropped
the DISPLAY statement with `errors=[]`. Fixed by calling the shared `is_statement_boundary()`
right after the period check in both loops.

### 2 — ENTRY's USING clause swallows a following statement **[verified, fixed]**
`cobolparser/parsers/statements/entry_parser.py`: `_parse_using_clause`'s fallback branch
accepted *any* token as a USING parameter. `ENTRY 'X' USING WS-X` (no period) followed by
`DISPLAY 'DONE'.` produced `using_parameters == ['WS-X', 'DISPLAY', 'DONE']` — the DISPLAY
statement vanished from the AST. Fixed the same way as (1).

### 3 — CALL exception/overflow handler drops unsupported verbs with no warning **[verified, fixed]**
`cobolparser/parsers/statements/call_parser.py`: `_parse_nested_stmts` (ON EXCEPTION / NOT ON
EXCEPTION / ON OVERFLOW bodies) silently consumed one token at a time when the registry had
no parser for a verb — inconsistent with the top-level PROCEDURE DIVISION dispatch loop,
which has warned since the 2026-07-07 C2 fix. `INVOKE FOO 'bar'` inside a CALL's ON EXCEPTION
vanished with `warnings=[]`; the identical statement at top level warns. Fixed by adding
`_warn_and_skip_handler_statement`, which mirrors
`ProcedureDivisionParser._warn_unsupported_statement`/`_skip_to_next_statement`: one warning
per dropped statement, then a single skip to the next statement boundary (not one warning per
token).

### 4 — Blank/comment/directive lines are dropped, silently shifting every later line number **[verified, fixed]**
`cobolparser/preprocess/__init__.py`'s `normalize_fixed_format` flushed the accumulated buffer
for a blank or comment line and then simply `continue`d — no placeholder was emitted for that
physical line. Every real COBOL program has blank/comment lines, so this shifted *every*
subsequent lexer/parser error and warning location by however many such lines preceded it.
Repro: a bad token on physical line 9 (source has one blank line and one comment line before
it) was reported as **line 7**. `preprocess_conditional_compilation` had the identical gap for
`>>DEFINE`/`>>IF`/`>>ELSE`/`>>END-IF` directive lines *and* for source lines inside a skipped
`>>IF` block. Fixed by emitting an empty-string placeholder for every dropped physical line in
both functions (and in the Cython `_preprocess_fast.pyx` mirror — `.c` regenerated), so output
line count always matches input line count.

### 5 — Cython/pure-Python lexer divergence in continuation-quote whitespace check **[verified, fixed]**
`cobolparser/_lexer_fast.pyx`'s `is_line_start_quote` check used `text[:pos].strip() == ""`
(Python's broad whitespace definition — `\v`, `\f`, NBSP, …) while the pure-Python lexer used
an explicit `char not in " \t"` loop. A stray control byte (plausible EBCDIC/ASCII transcoding
leftover) immediately before an unterminated quote made the compiled build classify the line
as a VALUE-clause continuation candidate differently from the fallback path for identical
input. Fixed by replacing the Cython `.strip()` call with the same explicit loop.

### 6 — `parse_files_with_copybooks` can abort the whole batch on one file **[verified, fixed]**
`cobolparser/batch.py`: unlike `parse_files`'s workers (fixed under 2026-07-07 C8), the
copybook-aware entry point had no exception guard around `parser.parse(...)` — a parse-time
exception on any file propagated out of the function, discarding every other file's
already-computed result. It also only caught `OSError` (not `ValueError`, which covers
`UnicodeDecodeError` under the documented `errors="strict"` option) on the file-read step.
Both fixed to match `parse_files`'s per-file fault isolation.

### 7 — `coverage generate` / `generate-tests -o` crash with raw tracebacks **[verified, fixed]**
`cobolparser/cli/coverage.py`'s `cmd_generate` didn't catch `json.JSONDecodeError` from
`IOCoverageReporter.load_pytest_results` (the identical M10 bug class already fixed for
`coverage status`); a non-object JSON root additionally raised an uncaught `AttributeError`
deep inside the loader. `cobolparser/cli/parse.py`'s `_cmd_generate_tests` wrote its `-o`
output file with no `OSError` guard, bypassing the `_fail(...)` pattern every other
output-writing subcommand uses. All three now fail cleanly with exit code 1 and a message.

## Not fixed (lower confidence / out of scope)

- `unlock_parser.py`/`accept_parser.py` accept any non-period token as their operand, which
  could theoretically swallow a following statement's verb *only* if the mandatory operand is
  itself missing from otherwise-malformed source — narrower and lower-impact than (1)-(3).
- `IOWriteStatement.advancing_mode` is set but not serialized in `to_dict()`; the same value
  is independently captured (correctly) in `advancing_clause`, so no data is actually lost —
  the unused top-level field itself is redundant, not a drop.
- `CobolFileDescription` (a fully-built AST node class with complete `to_dict()`) is never
  instantiated — FD/SD clauses are parsed into a raw dict on `metadata["fd_clauses"]` instead.
  Data isn't lost (it round-trips via `metadata`), so this is a dead-code/architecture
  observation, not a silent-drop bug.

## Verification

- Full suite: `python -m pytest tests/ -v` → **6,725 passed, 13 skipped, 5 xfailed**,
  92.68% coverage (floor 81%), both with and without the Cython extensions built.
- `ruff check .`, `black --check .`, `mypy cobolparser/` all clean.
- Cython extensions (`_lexer_fast`, `_preprocess_fast`, `_data_fast`) rebuilt from the edited
  `.pyx` sources via `python setup.py build_ext --inplace`; checked-in `.c` files regenerated
  and committed alongside the `.pyx` changes, per repo convention.
- New regression tests: `tests/regression/test_tier5_silent_drip_audit.py` (findings 1-3),
  `tests/regression/test_normalize_line_number_preservation.py` (findings 4-5),
  plus additions to `tests/integration/test_batch_coverage_gaps.py` (finding 6),
  `tests/unit/cli/test_coverage_cli.py` and `tests/unit/analysis/test_io_coverage_reporter.py`
  (finding 7).
