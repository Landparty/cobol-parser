# cobolparser — Repository Audit (2026-08-12)

Full-repo audit across five dimensions: core parsing pipeline, analysis &
generator subsystems, tests/CI/packaging, documentation consistency, and
security. Every finding below was verified against the code at HEAD
(`047ab64`, post-1.5.3) — file:line references included; failure scenarios
were reproduced where stated. Findings are numbered per section and ranked
by severity within each.

**Headline items (fix-first):**

1. **The test suite is red at HEAD** — commit `17fa400` changed EVALUATE
   WHEN selector quoting for all string literals, breaking the regression
   test that pins the contract (T-H1). Invisible because the full `test`
   job is `workflow_dispatch`-gated.
2. **CI lint should be failing on every push** — the lint job installs
   unpinned latest `black` (26.5.1), which reformats
   `tests/unit/test_flowchart_generator.py` (T-H2).
3. **`interface-contract.md` names an exception that doesn't exist** —
   the backend adapter contract says to catch `CobolParseError`; the
   package exports `ParseError` only (D-H1).
4. **`ConstantFolder` can emit provably wrong `field_equals`
   expectations** — conditional handler bodies (AT END etc.) are never
   poisoned, violating the module's "exact by construction, or absent"
   guarantee (A-A1); a second route via wrong paragraph ordering (A-A4).
5. **The OKF pre-commit hook never runs** — `.githooks/pre-commit` is
   committed non-executable, so git silently skips it (D-H2); and the
   `.claude/settings.json` PostToolUse hook documented in CLAUDE.md
   doesn't exist (D-H3). The staleness-prevention machinery is off, which
   is why the doc-drift findings below accumulated.

## 1. Core parsing pipeline (lexer / preprocess / parser / AST)

### Bugs

- **P-B1 — `MoveStatement.source` concatenates multi-word sources with no
  separator.** `cobolparser/parsers/statements/move_parser.py:223`
  (`"".join(source_parts)`). `MOVE WS-A OF WS-GRP TO WS-B.` →
  `source == "WS-AOFWS-GRP"`; `MOVE FUNCTION UPPER-CASE(WS-X) TO WS-Y.` →
  `"FUNCTIONUPPER-CASE(WS-X)"` (reproduced, parse reports success). Any
  consumer resolving qualified names (`ProgramLayoutIndex.resolve`,
  move-type checking, value tracking) gets a corrupted name. Should
  space-join with subscript-aware handling like `_consume_arithmetic_target`.
- **P-B2 — `TokenStream.expect()` accepts anything when the current token
  has an empty value.** `cobolparser/core/token_stream.py:79`
  (`if token.value and ...`). The EOF token has `value == ""`, so
  `expect(".")` at EOF consumes EOF and returns it instead of raising
  `TokenMismatch` (reproduced). Reachable from
  `parsers/divisions/identification.py:195/243/282` — a missing
  terminating period at end-of-file is silently accepted.
- **P-B3 — `ParseResult.statistics` aliases the parser's mutable state.**
  `parser.py:165` resets in place; `parser.py:620` passes
  `statistics=self.statistics` un-copied (errors/warnings are copied).
  Reusing one `CobolParser` clobbers earlier results:
  `r1.statistics is r2.statistics` is True (reproduced). Parser reuse is a
  supported pattern (`batch.py` executor reuse).
- **P-B4 — `_skip_to_identification_division` never matches
  sequence-numbered fixed-format source.** `parser.py:44`
  (`^\s*(IDENTIFICATION|ID)\s+...`): digits in columns 1–6
  (`000100 IDENTIFICATION DIVISION.`) never match, so junk before a
  numbered ID DIVISION fails the whole parse (reproduced). Allow a leading
  sequence area, e.g. `^[\s0-9]{0,6}\s*`.
- **P-B5 — Pure/Cython lexer divergence: compiled `tokenize()` never
  resets `self.warnings`.** `_lexer_fast.pyx:134-135` resets only
  `tokens`/`errors`; pure path resets all three (`lexer.py:1740-1742`).
  Two `tokenize()` calls on one compiled lexer duplicate every warning.
  Contradicts `.okf/lexer.md`'s explicit both-paths claim. Low practical
  impact (fresh lexer per parse) but exactly the drift class the parity
  tests exist to prevent.
- **P-B6 — `PathResolver` directory precedence is inconsistent across
  tiers.** `preprocess/path_resolver.py:325-336`: the Tier-2 index's
  full-filename key is last-directory-wins, the stem key first-wins, and
  Tier-3 `find_copybook_file` (line 239) is first-wins. `COPY "MEM.CPY"`
  present in two search dirs resolves to a different file depending on
  which tier serves the lookup. Precedence should be
  first-configured-directory-wins everywhere.

### Design / maintainability

- **P-D1 — `expand_copybooks()`'s `path_resolver` parameter is silently
  ignored.** Declared at `copybook_expander.py:514`, unconditionally
  overwritten at `:590` — a pre-warmed resolver (index reuse across a
  batch) is discarded with no error.
- **P-D2 — Hand-edited generated C file.** Commit `8197d5e` manually
  patched `cobolparser/_lexer_fast.c` (Windows-form `sources` path, zstd
  string-table block). Regeneration with the repo's exact cythonize
  settings (Cython 3.2.9) confirms functional parity today, but the
  checked-in artifacts encode one build machine's environment; the next
  regeneration on a zstd-less box produces a large spurious diff.
  Regenerate all three `.c` files from one canonical environment.
- **P-D3 — Cython `wraparound=False` + negative slice indices is formally
  undefined.** `setup.py:42`; cythonize warns at `_lexer_fast.pyx:142`
  (`line[:-1]`) and `_data_fast.pyx:75` (`token_value[:-1]`). Generated C
  is currently correct, but a Cython upgrade could silently break the hot
  path. Use explicit-length slices.
- **P-D4 — Statement columns are normalized-text coordinates, not source
  coordinates.** `normalize_fixed_format` strips columns 1–7; a statement
  at source column 12 reports column 5 (verified). Lines are carefully
  preserved; the column coordinate system is undocumented.
- **P-D5 — `ASTNodeFactory` validator registry is class-level shared state
  and never consulted.** `core/ast_factory.py:71` (`_node_validators` is a
  class attribute — one instance's `register_validator` mutates all
  factories) and `create()` (line 177) never reads it. The advertised
  field validation is unreachable through the creation path.
- **P-D6 — `find_all_by_type` returns the internal cache list.**
  `models/ast_base.py:184` — mutating the returned list corrupts
  subsequent lookups.

### Dead code

- **P-C1 — `parse_picture_clause_fast` (`_data_fast.pyx:25`) is never
  called** — the PIC branch calls back into Python
  (`_data_fast.pyx:183`). Hazard, not just clutter: the dead fast version
  lacks the 2026-07-21 missing-terminator LEVEL_NUMBER lookahead fix
  (unconditional `pos += 1` at `:91-92`); wiring it up later re-introduces
  the silent next-data-item drop.
- **P-C2 — Four unreachable `KEYWORDS` entries containing spaces**
  (`lexer.py:579/582/583/588`: `"KEY IS"`, `"WITH LOCK"`, `"NO REWIND"`,
  `"NO ADVANCING"`) — word readers can never produce a value with a space.
- **P-C3 — Legacy char-cursor lexer API is dead in production**
  (`read_string_literal` `lexer.py:742`, `read_numeric_literal` `:779`,
  `read_identifier` `:815`, `read_comment` `:846`,
  `read_string_from_text` `:1396`, `_compress_doubled_quotes` `:1485`,
  `peek_char`/`advance_char`/`skip_whitespace`) — called only from tests.
- **P-C4 — `TokenStream.transaction()` has no callers**
  (`core/token_stream.py:110-118`).
- **P-C5 — Discarded cache-key call** (`copybook_expander.py:760`) —
  result thrown away; the real key is built two lines later.
- **P-C6 — Dead newline-strip branches in both lexer variants**
  (`_lexer_fast.pyx:141-144`, `lexer.py:1748`) — `splitlines()` never
  yields `"\n"`. Harmless, but the two implementations "differ" only in
  unreachable code — noise for parity auditors.

### Verified clean

`normalize_fixed_format` pure vs `_preprocess_fast.pyx` are equivalent
(short-line threshold, indicator handling, quote-state machine incl.
doubled quotes, M5 trailing-blank rule, column-73 warning, EOF raise); the
other five `_lexer_fast` overrides match token-for-token; all 74 concrete
`ASTNode` subclasses implement `to_dict()`; line numbers propagate
end-to-end; the statement registry's two-token dispatch cache is sound.

## 2. Analysis & generator subsystems

### High-severity bugs

- **A-A1 — `ConstantFolder` never poisons conditional handler bodies —
  can emit wrong `field_equals` expectations.**
  `analysis/const_fold.py:328-343` deliberately passes on
  READ/ACCEPT, and the generic fallback (`:366-371`) poisons only
  `stmt.operands`; nothing poisons statements nested in
  `at_end_clause`/`invalid_key_clause`/`on_size_error`/`on_overflow`
  (its own `_NESTED_STATEMENT_ATTRS` at `:100-116` is used only for
  IF/EVALUATE/loop bodies). Scenario: `MOVE 'N' TO WS-EOF. READ F AT END
  MOVE 'Y' TO WS-EOF. DISPLAY WS-EOF.` — in the Phase-6 empty-input
  scenario (sequence length 0) the AT END fires at runtime, but the
  folder emits `field_equals WS-EOF = "N"`. Violates the "exact by
  construction, or absent" guarantee (docstring lines 15-17).
- **A-A2 — Flowchart external-call nodes read a key the analyzer never
  produces.** `generators/flowchart.py:257` and `:491` read
  `ext.get("target", "")`; `EdgeCollector.process_call`
  (`analysis/program_flow/edges.py:198-206`) emits `"program"` (plus
  `is_dynamic`/`called_from`/`location`). With any real
  `ProgramFlowAnalyzer` report, `show_external_calls=True` never emits the
  styled `EXT_*` nodes — the feature is dead end-to-end, masked by
  `tests/unit/test_flowchart_generator.py:135` hand-building
  `{"target": ...}`. Residual: `edge.target` is uppercased
  (`edges.py:192`) while `call_info["program"]` keeps original case.
- **A-A3 — CRUD matrix assigns the statement's first OPEN mode to every
  file in the statement.** `analysis/crud_matrix.py:329-337` uses
  `stmt.open_mode` for all `stmt.file_names`;
  `IOOpenStatement.file_modes` (`models/statements/io.py:320-326`) exists
  precisely for this and its comment names the CRUD matrix as the
  mis-keyed consumer. `OPEN INPUT IN-FILE OUTPUT OUT-FILE.` records
  INPUT for both files.
- **A-A4 — `ConstantFolder._ordered_paragraphs` is not source-ordered.**
  `const_fold.py:226-250` appends section-owned paragraphs then top-level
  ones, inverting real source order for mixed programs; PERFORM THRU span
  resolution (`:416-437`) then yields `end_idx < start_idx` → empty body →
  a stale prior value survives into a `field_equals` expectation (second
  route to a wrong expectation). Its docstring claims parity with
  `program_flow/scanner.py`, but scanner (`scanner.py:95-107`) and
  dead_code (`dead_code.py:173-184`) were both fixed on 2026-08-11 to
  interleave by source line; const_fold was not.
- **A-A5 — `BoundaryInventoryAnalyzer` and `ConstraintExtractor` silently
  skip statements nested in ON SIZE ERROR / NOT ON OVERFLOW / NOT AT EOP
  bodies.** `analysis/boundary_inventory.py:59-71` and
  `analysis/constraints.py:60-72` omit `on_size_error`,
  `not_on_size_error`, `not_on_overflow`, `not_at_eop_clause` — all real
  model attributes covered by `scanner.py:39-50` and const_fold's list.
  `ADD A TO B ON SIZE ERROR CALL 'ERRLOG'` produces no CALL boundary and
  no `unresolved` note — contradicting the "nothing silently dropped"
  posture.
- **A-A6 — `domains.solve()` can return a witness violating its own
  constraints.** `analysis/domains.py:69-76`: midpoint pick without
  snapping to the decimal grid + float-equality exclusion check +
  rounding in `ValueFactory.render` (`generators/data/values.py:418`).
  `PIC 9` with `ne "4"` → midpoint 4.5 → rendered `"4"` — the excluded
  value; the scenario pins the field to the wrong arm.
- **A-A7 — The "error status: OPEN → 35" fixed family can never fire.**
  `generators/scenarios.py:440` gates on OPEN boundaries having
  `status_field`, but `_classify_file_op`
  (`boundary_inventory.py:423-434`) never sets `status_field` for
  OPEN/CLOSE (only READ/DELETE/START/UNLOCK, `:469-474`). The documented
  scenario family silently never appears in `mode="all"`.

### Medium-severity bugs

- **A-B1 — `IOSequenceAnalyzer` treats `STOP 'literal'` as program
  termination.** `analysis/io_sequence.py:190-207` ignores
  `StopStatement.stop_type` (every other analyzer checks it:
  `dead_code.py:394-395`, `scanner.py:599-600`). A message-STOP yields
  spurious `FILE_LEFT_OPEN`, then `READ_BEFORE_OPEN`/`CLOSE_NOT_OPEN`.
- **A-B2 — Boundary keys are order-dependent and not actually unique.**
  `boundary_inventory.py:788-790` + `_unique_prefix` (`:727-739`) compare
  against previously assigned shortened keys, not sibling sites' full
  texts — the first of `SELECT A FROM T` / `SELECT B FROM T` keeps key
  `"SELECT"`, a prefix of the second site's text, breaking the documented
  mockymock prefix-matching convention.
- **A-B3 — `DynamicCallAnalyzer` records unrecognized identifiers as
  literal values.** `analysis/value_tracker.py:174-177` + `:101-112`:
  `MOVE WS-INPUT-PROG TO WS-TARGET` (no VALUE clause) pollutes
  `possible_values` with the variable name as if it were a program name.
- **A-B4 — Duplicate level-88 condition names resolve last-one-wins
  silently.** `generators/data/program_layout.py:361` overwrites the
  condition index with no `ambiguities` entry, unlike
  `resolve()`/`record_named()` which refuse to guess.

### Dead code

- **A-C1 — Empty-section branch in `ProcedureScanner.scan_statements`
  does nothing** (`program_flow/scanner.py:156-158`).
- **A-C2 — `parse_files_with_copybooks`'s `_file_content_cache` is
  created and never used** (`batch.py:334-335`) — the docstring's "shared
  file content cache avoids redundant I/O" is not delivered by this dict.
- **A-C3 — `scenarios._error_status_scenarios` OPEN branch unreachable**
  (same root cause as A-A7).

### Design concerns (lower priority)

- `MoveTypeChecker`'s flat name→category catalog
  (`move_type_checker.py:268-278`) collapses duplicate data names
  last-one-wins — false violations/passes possible, no ambiguity
  accounting.
- `DeadCodeAnalyzer` explicit references are not reachability-gated
  (`dead_code.py:251-267`) — dead subgraphs shield each other.
- `domains._apply_enum` ignores relational ops on an 88-enumerated domain
  (`domains.py:165-174`), and raw `"THROUGH:n"` markers can leak into
  `EnumDomain.values` and be picked as a witness.
- `detect_cycles` dedups by node *set* (`program_flow/cycles.py:61-64`) —
  distinct cycles over the same node set report once.

### Verified clean

Mermaid `linkStyle` index seeding; ADD/SUBTRACT GIVING fold semantics;
`range_members` out-of-order fallback; dead_code interleave/dedup/
fall-through logic; `write_csv_dir` path-escape sanitization; per-boundary
sub-seed determinism; `profiling.py` percall math; `_entry_paragraph`
top-level-first preference.

## 5. Security

No exploitable vulnerability on the default parse or copybook-expansion
path. One real defect:

- **S-1 (LOW/MEDIUM) — Exponential ReDoS in exported `COPY_PATTERN`
  regex (latent).** `preprocess/copy_statement_parser.py:72` (built from
  `_REPLACING_OPERAND`, line 56): the REPLACING sub-pattern is ambiguous
  (`BY` matches the identifier-operand alternative), so
  `COPY X REPLACING BY BY BY … BY %` (unterminated) backtracks
  exponentially — measured ~3.1× per +4 tokens (46 tokens: 0.46 s;
  58: 13.5 s; ~90 effectively unbounded). **Not reachable from the live
  expansion path** (the real `CopyStatementLexer.tokenize_copy_statements`
  at line 479 is a linear hand-written lexer), but `COPY_PATTERN` is
  **exported in `__all__`** (line 972) — any downstream consumer
  (including the vendored backend) using it on untrusted COBOL inherits
  the DoS. Fix: remove the dead pattern from the module and `__all__`, or
  de-ambiguate the REPLACING operand.
- **S-2 (INFO) — Batch workers have no per-file memory/time cap**
  (`batch.py:186`). Pickling itself is safe (only trusted internal
  objects cross the boundary). Document that batch input should be
  size-bounded.
- **S-3 (INFO) — CLI `-o` overwrites without confirmation**
  (`cli/parse.py:163,209`). Standard CLI behavior; noted so it stays a
  conscious choice.

### Checked and OK

Path traversal in `path_resolver.py` holds against symlinks (both the
resolving Tier-1 check and `_validate_indexed_result` on the Tier-2
index), `..` segments, absolute member names, encoding tricks, and
case-insensitive filesystems. Billion-laughs nested COPY is bounded by
depth (100), per-file (10 MB) and cumulative (100 MB) caps enforced on
both cache-miss and cache-hit/diamond paths. `detect_encoding` reads a
