# cobolparser Audit — Gap Analysis (2026-07-06)

Scope: `cobolparser` 1.1.0. Method: static review of lexer, preprocessing, parser,
statement parsers, AST models, analyzers, tests + CI, backed by empirical probes
(NIST COBOL-85 corpus sweep of 459 programs, targeted malformed-input tests, and
AST-fidelity checks). Findings marked **[verified]** were reproduced at runtime;
**[reported]** are from code review and are credible but not each independently run.

## Headline

The parser is **robust against crashes** (0 crashes across the 459-file NIST corpus
and a malformed-input fuzz set) but **too lenient about correctness**: it routinely
reports `errors=0` while producing an AST that is silently wrong. Two structural
root causes drive most of the high-severity findings:

1. **No shared "end-of-statement" predicate.** Each statement parser re-implements
   boundary detection ad hoc. Recent commits fixed the "swallow the next statement"
   bug one verb at a time (ADD/MOVE-target/COMPUTE/IO clauses), but the same bug is
   **still live** in INSPECT, STRING/UNSTRING, the MOVE *source* path, EXEC SQL/CICS/IMS,
   and `ON SIZE ERROR` bodies.
2. **Two divergent AST traversal APIs.** `find_all_by_type()` / `traverse_depth_first()`
   (walks `children`) disagree with `get_all_statements()`. Statements nested in
   `EVALUATE` are reachable by one and invisible to the other.

---

## HIGH severity

### H1 — `find_all_by_type` silently misses everything inside EVALUATE **[verified]**
`EvaluateStatement` stores its `WhenClause`s (and their statements) in a `.when_clauses`
attribute but **never registers them as AST `children`**. Because `find_all_by_type`,
`find_first_by_type`, and `traverse_depth_first` (`models/ast_base.py:137-184`) only
walk `children`, any statement inside a WHEN branch is invisible to them.

- `EVALUATE` is the *only* container with this defect: IF, ELSE, inline PERFORM,
  SEARCH, READ…AT END, and STRING all correctly register nested statements as children.
- Reproduction: a program whose only `MOVE`/`PERFORM`/`DISPLAY` lives in a WHEN branch
  returns `0` from `find_all_by_type("MoveStatement")` but the statement *is* returned
  by `get_all_statements()`.
- Impact: the README's documented public API (`ast.find_all_by_type("MoveStatement")`)
  returns wrong results, and the **vendored backend** plus any analyzer using it will
  silently under-count. Analyzers that happen to use `get_all_statements()` (e.g.
  `CRUDMatrixGenerator`) are correct — the inconsistency is the real hazard.

### H2 — "Swallowing" boundary bug still live in several verbs **[verified]**
When these statements are not terminated by a period, they consume the *following*
statement and report `errors=0`:

| Verb | Location | Verified behavior | Status |
|------|----------|-------------------|--------|
| INSPECT | `statements/initialize_inspect_parsers.py:164-179` | eats trailing statements to next period | **Fixed 2026-07-06** |
| STRING | `statements/string_unstring_parsers.py:150-151` | eats following `DISPLAY`/`ELSE`/`END-IF` | **Fixed 2026-07-06** |
| UNSTRING | `statements/string_unstring_parsers.py:257-258` | same | **Fixed 2026-07-06** |
| MOVE (source path) | `statements/move_parser.py:143-182` | `MOVE A` (no `TO`) swallows next statement | Open |
| EXEC SQL/CICS/IMS | `statements/ibm_exec_statements.py` + `_utils.py:764-809` | missing `END-EXEC` consumes rest of program | **Fixed 2026-07-06** (now reports an "Unterminated EXEC block" error instead of silently swallowing) |

These parsers never consult the `STATEMENT_KEYWORDS` / `SCOPE_TERMINATORS` /
`CONTROL_FLOW_BOUNDARIES` guards that the patched verbs now use.

**Resolution (2026-07-06):** INSPECT/STRING/UNSTRING now route through a shared
`is_statement_boundary()` predicate (`statements/_utils.py`) and stop at the
following statement instead of consuming to the next period. EXEC-* cannot use
that content predicate (embedded SQL legitimately contains SET/DELETE/UPDATE/
CALL/OPEN/CLOSE), so `collect_exec_sql_text` now reports a non-fatal
"Unterminated EXEC block: missing END-EXEC" parse error when the mandatory
`END-EXEC` is absent — the silent `errors=0` swallow becomes `success=False`.
Pinned by four new classes in
`tests/regression/test_tier2_silent_drop_regressions.py`. The **MOVE source
path** row remains open (not in scope for this change).

### H3 — Silent acceptance of malformed / incomplete input **[verified]**
All of the following return `errors=0` with a plausible-but-wrong AST:
- `MOVE A TO.` → `MoveStatement` with `targets: []` (invalid COBOL, no error).
- `MOVE A` (no `TO`) → accepted.
- `COMPUTE X = ((A + B)` (unbalanced parens) → accepted.
- 200 unclosed `IF`s with no bodies → accepted.
- Truncated `MOVE A TO` at EOF → accepted.

The procedure parser's fall-through (`divisions/procedure.py:346-388`) skips
unrecognized tokens **without calling `add_error`**, and treats leftover tokens as
phantom paragraph names. Downstream consumers get no signal that anything went wrong.

### H4 — Inverted AND/OR precedence in IF conditions **[verified]**
`if_parser.py:257` splits on the first of `("AND","OR")` it finds, making `AND` the
tree root. `IF A = 1 OR B = 2 AND C = 3` parses as `(A OR B) AND C` — semantically
wrong; COBOL binds `AND` tighter than `OR`, so it should be `A OR (B AND C)`. Any
analysis that reads the condition tree gets inverted logic, silently.

### H5 — Unterminated literal aborts the whole parse, defeating COLLECT_ALL **[verified]**
`normalize_fixed_format` raises `ValueError` on an unterminated literal
(`preprocess/__init__.py:530-534`), called unconditionally from `parser.py:182`
*before* error-recovery is active. Result: one bad literal → `ast=None`, the entire
program is lost even under `ErrorRecoveryMode.COLLECT_ALL`.

## MEDIUM severity

### M1 — Nested-clause bodies drop non-trivial statements **[verified/reported]**
- `ON SIZE ERROR` / `NOT ON SIZE ERROR` bodies only capture `DISPLAY` and `MOVE`
  (`_utils.py:812-918`). **[verified]** `ON SIZE ERROR PERFORM ERR-PARA` → the PERFORM
  is dropped, `errors=0`. Affects all of ADD/SUBTRACT/MULTIPLY/DIVIDE/COMPUTE.
- `try_parse_nested_statement` (`_utils.py:522-560`) wraps nested parsing in a bare
  `except Exception: return None`, so malformed statements inside IF/PERFORM/EVALUATE/
  SEARCH/IO bodies vanish with no error under COLLECT_ALL. **[reported]**

### M2 — Fixed-format column extraction is naive **[verified]**
`normalize_fixed_format` (and the lexer's own handler) slice `line[7:72]` by raw
character index with **no tab expansion**. A single leading tab shifts every column;
`\t\tDISPLAY X` normalizes to `AY X` and the statement is silently lost. Tabs are
common in Git-stored / hand-edited COBOL.

### M3 — Debug lines (`D` in column 7) emitted as live code **[verified]**
`normalize_fixed_format` treats only `*`/`/` as comment indicators
(`preprocess/__init__.py:491`); a `D`/`d` indicator falls through and the debug
statement is inlined as *active* code. Per standard COBOL these are inactive unless
`WITH DEBUGGING MODE`. Contradicts `is_comment_line` in `copy_statement_parser.py:281`,
which *does* treat `D` as a comment.

### M4 — Expressions stored as raw strings, not parsed **[reported]**
COMPUTE (`arithmetic_parsers.py:513`), PERFORM…UNTIL (`perform_parser.py:390`), and the
IF fallback (`if_parser.py:297`) store their expression/condition as a joined string.
No operand/operator tree is built for these very common constructs, so structural
analysis of arithmetic and loop/branch conditions is impossible.

### M5 — Two divergent fixed-format implementations **[reported]**
`parse()` normalizes to free-form then lexes with `free_form=True` — so the lexer's
~200-line fixed-format handler (`lexer.py:826-1024`) is dead for the parse path but is
still used by `tokenize_cobol()` / CLI `tokenize` (defaults `free_form=False`).
`tokenize` and `parse` therefore run different column logic and can produce different
token streams (one drops comments, the other emits COMMENT tokens).

### M6 — EXEC SQL/CICS/IMS are raw-text stubs **[reported]**
Only a command name + flat text blob is captured; host variables, SQL clause
structure, and CICS/IMS options are unparsed. Combined with H2 (missing `END-EXEC`
swallows the program), SQL-heavy programs get low-fidelity ASTs.

### M7 — Conditional compilation not wired into the parse path **[verified]**
`preprocess_conditional_compilation` is a standalone step (CLI `preprocess` only), not
called by `parse_cobol`; `>>IF/>>END-IF` directives are effectively ignored by `parse`
(guarded code always kept, no error). When the function *is* used, only
`symbol IS [NOT] DEFINED` is understood — every other condition (`>>IF A > 5`) hits a
"default to skipping" branch and the block silently vanishes
(`preprocess/__init__.py:590-605`). `>>EVALUATE` is documented but unimplemented.

### M8 — Path-traversal validation has a symlink gap **[reported]**
`validate_path_within_directory` is only called in the Tier-3 resolver
(`path_resolver.py:255`); the Tier-2 directory-index fast path
(`path_resolver.py:362-394`) returns the indexed absolute path with no containment
check, so a symlink inside a copybook dir pointing outside the search root is read
unchecked. The `".." in file_path` check (`:62`) is also naive substring matching.

### M9 — Typed literals not decoded **[reported]**
`X'..'`, `N'..'`, `NX'..'`, `G'..'` store raw inner text as `.value`
(`lexer.py:1245-1307`); `X'1F'` yields `value="1F"`, not byte `0x1F`, with no hex
validity/even-length check. Consumers reading `.value` get wrong content.

### M10 — Line-count fidelity loss → wrong error locations **[reported]**
Blank/short lines are dropped rather than re-emitted during normalization
(`preprocess/__init__.py:475-487`), so free-form line numbers drift from the source
after the first blank line — reported error locations are off.

## LOW severity

- **L1** REPLACING is context-blind text substitution (hits string literals/comments;
  `:...:` pseudo-text broken in the lexer path). `copy_statement_parser.py:396-405,725-775` **[reported]**
- **L2** No `*>` inline-comment support (lexes as `MULTIPLY_OP`+`GREATER`). **[reported]**
- **L3** EBCDIC autodetection is a fragile byte-count heuristic; Latin-1/CP1252 fall
  back to lossy `errors="replace"` with silent U+FFFD substitution. `copybook_expander.py:196-259` **[reported]**
- **L4** `ALL` is always a figurative constant, never the `ALL` keyword (`TokenType.ALL`
  is unreachable) → `INSPECT … REPLACING ALL` sees the wrong token. **[reported]**
- **L5** GO TO … DEPENDING ON with multiple targets keeps only the first target. `go_parser.py:99-105` **[reported]**
- **L6** ACCEPT is minimal (no `ON EXCEPTION`, `WITH NO ADVANCING`, `AT LINE/COL`,
  date-format phrases); trailing phrases left dangling. `accept_parser.py:34-64` **[reported]**
- **L7** Editing PICTURE strings (`PIC 99/99/99`, `PIC 99.99`) are lexed as
  operators/numbers; correctness depends on the DATA parser reassembling them. **[reported]**
- **L8** Dead code: `_compress_doubled_quotes` (`lexer.py:1398`) never called and would
  corrupt cross-quote literals if wired in. **[reported]**

## Test & tooling gaps

- **CI never builds or exercises the Cython fast path.** `.github/workflows/ci.yml`
  has no `build_ext`; the accelerated `_lexer_fast` / `_preprocess_fast` / `_data_fast`
  paths ship untested by CI. **[verified]** The only comparison tests are perf
  benchmarks — nothing asserts token-stream *identity* between fast and pure paths, and
  two latent divergences already exist (`_lexer_fast.pyx:289` `str.strip()` vs
  `" \t"`-only; `:142` `line[:-1]` vs `rstrip("\n")`). **[reported]**
- **`batch.py` is the worst-covered module at 61%** — the entire `ProcessPoolExecutor`
  path and all of `parse_files_with_copybooks` are untested. **[reported, coverage.json]**
- **12 permanently-skipped copybook-expansion tests** (`pytest.skip("Implementation
  pending - Phase 6/7")` across unit/integration/contract suites) silently defer a whole
  feature area. **[reported]**
- Biggest branch-coverage holes: `divisions/data.py` (48 missing branches),
  `divisions/environment.py` (40). Statement parsers PERFORM/CALL/STRING/UNSTRING lack
  isolated unit tests and show it in their branch numbers. **[reported]**
- `path_resolver.py` security-*rejection* paths (the traversal-prevention branches) are
  among the uncovered lines — the exact code a security module most needs tested. **[reported]**
- Documented, honestly-marked `strict=True` xfails: `OBNC1M.CBL` (comment-entry Area A/B
  termination) and `SM101A.CBL` (needs copybook expansion). Good hygiene, but real
  parser limitations.

## Recommended priorities

1. **Introduce one shared end-of-statement predicate** and route INSPECT, STRING/UNSTRING,
   MOVE-source, EXEC-*, and `ON SIZE ERROR` bodies through it (fixes H2, most of M1). This
   is the single highest-leverage change — it retires the recurring "swallow" class.
2. **Register EVALUATE WHEN statements as AST children** (or make the traversal API
   EVALUATE-aware) so `find_all_by_type` and `get_all_statements` agree (H1).
3. **Emit an error on unrecognized/incomplete statements** instead of silently skipping
   (H3) — even a single "unparsed tokens" diagnostic would surface the whole silent-wrong
   class to callers.
4. Fix AND/OR precedence (H4) and stop aborting the whole parse on one bad literal (H5).
5. Add a **fast-vs-pure token-identity test** and build the extension in CI.
6. Expand fixed-format normalization to handle tabs and `D` debug lines (M2, M3).
